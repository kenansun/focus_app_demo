# Local Data & Logic Analysis (Offline-First)

This document outlines the data requirements and logic for the Focus App as a fully offline, local-first application. All data will be persisted locally (e.g., SQLite, IndexedDB, or LocalStorage).

## 1. Core Data Entities (Local Database Schema)

We need to model the data relationships to be stored in a local database.

### 1.1 User Profile (Singleton)
Since there is no login, we maintain a single local user profile.
*   **Source**: Local Storage / DB
*   **Fields**:
    *   `username`: Display name (default: "User")
    *   `avatar`: Local path or selected asset ID.
    *   `rewardBalance`: Current available "Play Time" (minutes). (Computed or stored as a running balance)
    *   `totalFocusTime`: Lifetime accumulated focus minutes.

### 1.2 Focus Session (History Log)
The immutable record of every focus attempt.
*   **Source**: Generated by the **Focus Timer** page, stored in Local DB.
*   **Fields**:
    *   `id`: UUID
    *   `startTime`: Timestamp (ISO8601)
    *   `endTime`: Timestamp (ISO8601)
    *   `durationMinutes`: Integer (Actual time spent)
    *   `mode`: 'focus' | 'play' | 'task'
    *   `status`: 'completed' | 'abandoned'
    *   `rewardChange`: Integer (+minutes for focus, -minutes for play)
    *   `taskId`: UUID (Optional, links to a Task if in Task Mode)

### 1.3 Tasks
User-created goals.
*   **Source**: User input on **Tasks** page.
*   **Fields**:
    *   `id`: UUID
    *   `title`: String
    *   `targetMinutes`: Integer (Goal)
    *   `accumulatedMinutes`: Integer (Current Progress) -> *Updated by completing Sessions*
    *   `status`: 'active' | 'completed' | 'abandoned'
    *   `createdAt`: Timestamp

### 1.4 App Groups (Blocking Rules)
Configuration for which apps are blocked/allowed.
*   **Source**: User configuration on **App Groups** page.
*   **Fields**:
    *   `id`: UUID
    *   `name`: String (e.g., "Work", "Social")
    *   `icon`: String (Asset name)
    *   `color`: String (Hex or Tailwind class)
    *   `packageNames`: List<String> (Array of Android/iOS package IDs)

### 1.5 App Settings
Global configuration.
*   **Source**: **Settings** page.
*   **Fields**:
    *   `focusDuration`: Default 25m
    *   `rewardDuration`: Default 5m (Reward ratio)
    *   `usageThreshold`: Daily limit (e.g., 120m)
    *   `permissionsState`: Cached state of system permissions.

## 2. Page Logic & Data Flow

### 2.1 Home Page
*   **Data Sources**:
    *   **User Profile**: Read `username`, `avatar`.
    *   **Focus Sessions (Query)**:
        *   `todayFocus`: Sum `durationMinutes` where `startTime` is today AND `mode`='focus'.
        *   `streak`: Calculate consecutive days with activity from Sessions table.
        *   `rewardBalance`: Read from User Profile (or calculate sum of all `rewardChange`).
    *   **Tasks (Query)**: Find active task with highest priority (or just first active) for "Daily Goal".
*   **Logic**:
    *   Calculates "Today's Focus" dynamically from the local session history.
    *   Navigates to Focus Timer with `mode='focus'` or `mode='play'`.

### 2.2 Focus Timer Page
*   **Data Sources**:
    *   **Input**: Receives `mode`, `taskId` (optional), and `targetTime` via navigation params.
    *   **Settings**: Reads `focusDuration` and `rewardDuration` to calculate rewards in real-time.
*   **Logic (State Machine)**:
    *   **Start**: Records `startTime`.
    *   **Tick**: Updates UI every second.
    *   **Stop/Complete**:
        1.  Calculates final `duration`.
        2.  Calculates `reward` based on Settings (if Focus mode) or consumption (if Play mode).
        3.  **Writes to DB**: Creates a new **Focus Session** record.
        4.  **Updates Task**: If `taskId` exists, increment `accumulatedMinutes` in the **Tasks** table.
        5.  **Updates Profile**: Update `rewardBalance` and `totalFocusTime`.

### 2.3 Tasks Page
*   **Data Sources**:
    *   **Tasks Table**: `SELECT * FROM Tasks WHERE status != 'archived'`.
*   **Logic**:
    *   **Create**: Inserts new row into Tasks table.
    *   **Continue**: Navigates to Focus Timer with `taskId`.
    *   **Complete/Abandon**: Updates `status` in Tasks table.

### 2.4 History Page
*   **Data Sources**:
    *   **Sessions Table**: `SELECT * FROM Sessions ORDER BY startTime DESC`.
*   **Logic**:
    *   **Filter**: Apply in-memory or SQL `WHERE` clauses for Date Range and Mode.
    *   **Grouping**: Group raw rows by Date for the UI list.

### 2.5 App Groups Page
*   **Data Sources**:
    *   **App Groups Table**: List all groups.
    *   **System Installed Apps**: (Native Module required) List of actual apps on the phone to allow selection.
*   **Logic**:
    *   **Edit**: Update `packageNames` list for a group.

## 3. Implementation Strategy (Offline)

Since we are moving to a purely offline model, we need a robust local persistence layer.

*   **Database**: **SQLite** (via `react-native-sqlite-storage` or `expo-sqlite`) or **WatermelonDB** (for reactive UI).
    *   *Recommendation*: For this demo, we can abstract this with a **Service Layer** that currently uses `AsyncStorage` (or `localStorage` for web demo) but is structured to swap in SQLite easily later.

*   **State Management**:
    *   Use **React Context** or **Zustand** to hold the "live" data (User Profile, Active Tasks) and sync with the Persistence Layer.

### Revised Architecture Diagram

`UI Components` <--> `Data Hooks (useTasks, useHistory)` <--> `Service Layer (TaskService, SessionService)` <--> `Local Storage / DB`

No Network Requests required for core functionality.
